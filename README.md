# frappe-native-multihand

Disposable Frappe development benches without Docker.

This is the native-host counterpart to [frappe-multihand](https://github.com/esafwan/frappe-multihand). It provides the same isolation ideas—protected reference state, per-task benches, allocation tracking, live testing, and cleanup—but assumes native MariaDB/Redis and a normal Linux Frappe installation.

## Why native?

Some managed development hosts do not provide Docker or passwordless system administration. This workflow works with the services already installed on the host and can be reached over SSH. It does not assume a particular Frappe app, company, customer, bench name, or cloud provider.

## Quick start

```bash
cp examples/config.example.env .env
${EDITOR:-vi} .env
examples/mh doctor
examples/mh new feature-x --dry-run
examples/mh new feature-x
examples/mh testplan feature-x --output testplan-feature-x.md
examples/mh teardown feature-x --dry-run
examples/mh teardown feature-x
```

Read [docs/native-workflow.md](docs/native-workflow.md) before provisioning a real bench. The examples are deliberately conservative templates: they fail closed when host-specific values or database credentials are missing.

## Safety

- The reference bench and site are protected by name and path guards.
- Disposable benches receive unique site, database, Redis, and port allocations.
- Temporary web servers bind to `127.0.0.1`.
- Teardown is scoped to one registry record and refuses the reference target.
- Secrets and backup files are ignored and are never generated by the repository.
